Architecture · design phase

Local Photo Search Architecture

Two phases share one store. An offline pipeline indexes David's ~150K-asset Photos library once per photo or video, entirely on-device. A runtime agent answers natural-language queries by calling back into that same index. Nothing leaves the Mac Studio. Built as the first of what's meant to become several local connectors into a broader personal-AI system — email and texts are likely future candidates — so the agent and store stay generically named on purpose, even though only this one is being built right now.

Indexing — offline, once per asset

Photos Library
Source of truth. Read-only access to the original files plus Photos.sqlite metadata (dates, named people, existing keywords). Never written to.
Keyframe extraction
Scene-change detection (FFmpeg or PySceneDetect) picks one representative frame per shot. Images skip this step entirely and go straight to per-frame processing.
Qwen3-VL (MLX)
30B-A3B mixture-of-experts vision-language model, ~18GB active memory at 4-bit quant — comfortably fits in 64GB. Generates tags and free-text captions per image/keyframe.
SigLIP2
Cross-modal embedding model. Turns each image/keyframe into a vector so a typed query like "beach" can be matched by meaning, not just keyword. Same embedding also gives a near-free zero-shot screenshot/document flag — compare it against label prompts like "screenshot" or "receipt," no extra model needed (the SnapSort approach).
Expression scorer
A cheap classical face-expression model (py-feat/DeepFace-style), run per detected face, scoring smile intensity and visible happiness. Reliable for a known, recurring axis — not for open-ended traits like "silly" or "funny" (see VLM pairwise judge below).
Quality scorer
Reuses the sharpness/exposure scoring already built for the dedup project, plus Q-Align for aesthetic and video quality. For video specifically, also folds in a cheap activity signal (motion/optical-flow variance, scene-change count, transcript density) as a candidate flag for "nothing happens here" — never a verdict on its own.
Duplicate grouper
Perceptual hashing (phash) clusters near-identical shots taken in succession — the same technique already proven in the dedup project's dedup.sqlite. Surfaces a suggested best-in-group; you still pick and delete manually.
Transcription
Whisper (MLX or whisper.cpp), run locally on each video's audio track. Writes a timestamped transcript straight into the store — enables search over what was said, not just what's visible, and feeds the quality scorer's activity signal above.
sqlite-vec
One SQLite file holding metadata, vectors, tags, quality/duplicate/transcript data together — same pattern as the existing dedup.sqlite, no second storage system to run. Also carries a plain FTS5 full-text index over tags/captions/transcripts, alongside the vectors, for the hybrid search below.

Query — runtime, per request

User query
Natural language, e.g. "show me the best Christmas pictures from each year." No query syntax to learn.
Agent loop (Qwen3)
A local tool-calling model that decomposes a query into steps — search per year, rank each year's results, compose an answer — and can retry a bad step.
Tools
semantic_search(query, filters) — hybrid: FTS5 keyword hits and SigLIP2 vector hits combined by Reciprocal Rank Fusion, not vector-only — plus get_photo_metadata(id) and rank_by_quality(ids). All three read the same sqlite-vec store built during indexing.
VLM pairwise judge
For traits with no stable per-photo score — humor, "best moment", mood — the agent skips the store and asks the VLM to compare candidates directly, pairwise, over just the narrowed set. Same judge-only-in-pairs discipline as the planned eval harness.
Ranked results
The agent's final answer — e.g. one best photo per year — ordered by the quality scorer, not just relevance.

Status: design only, no code yet — this diagram reflects research and decisions made before the Mac Studio arrives. Planned build order once it does: eval harness first, then the indexing pipeline, then the agent loop.

Principle: every score, group, or ranking this system produces — best-in-burst, suggested Christmas favorite, "might be boring" — is a suggestion surfaced for review. Nothing here writes back to Photos or deletes a file; that action stays manual, always.

Scope: photos/video is the only connector being built. Email and texts are plausible future connectors to the same agent and store pattern, not current work — and texts/email involve other people's words, which deserves its own privacy conversation before it's ever built, not just an extension of the no-cloud rule above.

Operation: two loops, not one continuously-running system. A cheap watcher (launchd, no AI involved) checks Photos.sqlite on a schedule for anything new — same shape as the existing HA/media-server watchdogs. Once enough new assets accumulate, a batch job loads the indexing models, processes them, and releases the memory, rather than reloading an 18GB model per photo. The query side loads its model on demand when asked, not kept resident all day.
